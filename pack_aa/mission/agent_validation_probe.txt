Findings from current implementation/output
--------------------------------------------
1. AA0 provenance is not exact: config/input is a 1,000-event materialized
   derivative while prepare_input.py:1-2,26-48 says it repeats a 100-event
   source ten times. The run AA0 record has different source_lhe_sha256 and
   input_lhe_sha256, yet pack_aa.py:285 labels AA0 PASS. This needs an explicit
   derived-input provenance rule or must fail the "exact frozen product" gate.
2. AA0/AA1 omit the declared weighted_input/<init> check from the contract
   (PACK_AA_DESIGN_CONTRACT.md:162-166); validate() at pack_aa.py:94-166 only
   extracts event weights and never parses the LHE weight mode.
3. AA1 is weaker than its schema: validate() hard-codes daughter masses/PDGs
   in pack_aa.py:32,136-138 instead of checking the pinned Pythia database, and
   does not enforce required fields such as executable_or_library,
   production_sample_id, self_conjugate, is_resonance, or a named partial-width
   placeholder (config schema:10-22,47-62,64-79).
4. AA2 does not implement the approved output-reader check. analyse_events()
   at pack_aa.py:227-236 checks counts, positive proper time, and finite proper
   length only; pack_aa.py:305-318 also does not prove a single decay, finite
   four-vertex, or configured/direct-daughter equality. The observed event has
   h2AllCount=8..30 and h2AfterCount=2; `hasVertex=false` is emitted by
   pack_aa/src/pack_aa_driver.cc:81, but no gate assertion interprets it.
5. AA3 is not a per-run gate: run_one() hard-codes
   aa3=PENDING_DEMO_REPRODUCIBILITY at pack_aa.py:291. The demo report hashes
   canonicalized JSON at pack_aa.py:341-348 and hard-codes accounting_identity
   true; no run summary contains output_file_hashes, event-loss reasons, or a
   computed full accounting identity.
6. Accounting is semantically under-specified: events_in/out are 1,000 events,
   while n_decayed_h2 and per_channel_generated_count are 2,000 h2 decays
   (run_summary.json:33-43,44-53). This is usable only if the schema declares
   N as h2 observations; the approved T5/T6 text calls N "decayed events"
   (TECHNICAL_DECISIONS.md:322,358). The probe must assert the denominator
   explicitly and never compare channel counts to events_out.
7. AA4/AA5 statistical implementation diverges from approved T6: AA4 uses the
   Wilson-Hilferty approximation (pack_aa.py:207-211), which is acceptable only
   at its stated N ceiling, but AA5 uses the normal band/fallback `count > 0`
   (pack_aa.py:246-253) and never implements the required Clopper-Pearson branch
   (TECHNICAL_DECISIONS.md:353-383). Also `events_failed_decay` becomes
   `expected-len(records)` only when global h2_ok is false (pack_aa.py:258),
   so structural failures can leave accounting_identity=true.
8. AA6 PASS is a claim, not four assertions: analyse_events() returns AA6 from
   only weight_ok and h2_ok (pack_aa.py:260-266). It never compares sigma,
   hard-process identity, event IDs/order, or input/output pre-decay h2 identity
   as required by VALIDATION_MATRIX.json:114-125.
9. Provenance is incomplete: the current run_summary lacks
   pack_aa_schema_version, implementation hash, frozen ZIP/input hashes,
   production sample ID, Pythia/compiler versions, channel seed, output hashes,
   and exit status. This contradicts VALIDATION_MATRIX.json:3-24 and the
   implementation mission at PACK_AA_IMPLEMENTATION_MISSION.md:41-42. No
   event-summary schema exists to catch the omission.
10. AA7 remains correctly non-final but is not tested under the addendum:
    PACK_AA_DESIGN_ADDENDUM_V1.md:109-119 requires a separate `.cmnd` syntax/
    in-process smoke, while run_one() only writes a fixed provisional reason at
    pack_aa.py:291. The old HepMC2 file-open requirement in
    VALIDATION_MATRIX.json:128-138 is superseded and should not be reported as
    a completed reader validation.

Read-only conclusion: existing artifacts support AA0/AA1/AA4/AA5 claims only
